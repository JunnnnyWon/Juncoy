# 구조와 설계 결정

## 프로세스와 저장 책임

| 구성               | 역할                                                     |
| ------------------ | -------------------------------------------------------- |
| apps/bot           | Discord Gateway·명령·감지 회차·진행자·음성 수신·STT 연결 |
| apps/api           | OAuth·세션·권한·목록·전사·검색·SSE·내보내기·정적 웹      |
| apps/web           | 한국어 전사·요약·근거·필터·연결 상태                     |
| apps/worker        | 파일 재전사·요약·outbox·보관·삭제·예산 알림              |
| packages/contracts | 공유 Zod 스키마와 DTO                                    |
| packages/domain    | 상태 전이·권한 비트·reducer·시간·요약 검증               |
| packages/db        | SQL 마이그레이션·트랜잭션·상태 원본·작업 큐              |
| packages/providers | ReturnZero·Solar·암호화·mock·스트리밍 슬롯 풀            |

PostgreSQL은 확정 전사, 단기 draft, 이벤트, 작업·타이머·게시 결과의 원본입니다. Redis는 사용하지 않습니다. API가 내려가도 봇은 웹 시청자 수와 무관하게 음성을 처리합니다. 파일 인코딩과 Opus 디코딩은 HTTP·Gateway 이벤트 루프 밖에서 수행합니다.

## 기록과 동시성

길드별 열린 음성 회의에 부분 UNIQUE를 적용합니다. 시작은 길드 advisory lock과 interaction 고유 키로 직렬화하고, 음성 소유자는 15초 lease를 4초마다 갱신합니다. fencing token은 길드별로 증가합니다. STOPPING은 음성 슬롯을 계속 점유하고 연결 해제 후 FINALIZING에서 반환합니다.

공개 상태 변경은 meeting 행과 event counter를 같은 순서로 잠급니다. 데이터·event_seq·공개 DTO 이벤트·후속 job/outbox를 한 트랜잭션에서 저장합니다. 전역 sequence의 선할당과 커밋 순서 역전을 허용하지 않습니다. NOTIFY는 깨우기·무효화 신호이며 이벤트 본문은 DB에서 읽습니다.

partial은 draft에만 저장합니다. final은 canonical 테이블과 버전 이력에 저장하고 draft를 제거합니다. 같은 source key의 final 반복, final 뒤 partial, 재처리 작업 재실행을 멱등 처리합니다. 동일 문장을 다른 시점에 말하면 별개 발언입니다. 파일 재전사는 이전 ID를 tombstone·replacement 관계로 연결하고 원문과 표시문을 분리합니다.

## 스트리밍 10개와 대기열

초기 계획의 동시 연결 20개 가정은 실제 계정 시험 결과와 사용자 요청에 따라 **10개 + FIFO 대기열**로 변경했습니다. 슬롯은 연결 준비부터 종료 완료까지 점유합니다. 반환 즉시 가장 오래 기다린 화자를 연결하며, 철회·이탈한 대기자는 제거합니다.

대기자가 없으면 15초 무발화 후 연결을 정리합니다. 대기자가 있으면 800ms 무발화 연결을 먼저 마감합니다. 계속 말하는 화자가 모든 슬롯을 점유할 때는 60초 이상 연결을 교대하여 오래 기다린 화자에게 기회를 줍니다. 교대 시 이미 전송한 원음을 다시 보내지 않으며 stream_epoch를 새로 부여합니다.

대기 버퍼는 화자당 최대 5초입니다. 더 오래된 음성은 암호화 원음에 남기고 파일 복구 범위를 기록합니다. 대기 중 발화가 끝나면 실시간 슬롯을 계속 기다리게 하지 않고 파일 재전사 작업으로 넘깁니다. 파일 요청은 공급사 job ID를 보관해 폴링하며 완료 전에는 작업을 다시 예약합니다.

## 개인정보와 보안

Discord 사용자 ID가 기본 화자입니다. 녹음 고지·동의 이후만 수집하며, 철회·일시정지는 캡처 진입점과 아직 보내지 않은 버퍼를 차단합니다. OAuth 토큰과 원음은 별도 키의 AES-256-GCM으로 암호화합니다. 원음 파일은 랜덤 nonce와 파일 ID AAD로 인증합니다.

브라우저에는 서버 발급 불투명 세션 쿠키만 전달합니다. 현재 길드 멤버십, 팀/관리자 여부, 기록 채널 ViewChannel·ReadMessageHistory를 확인합니다. 캐시 유효기간은 실제 검증 시작부터 최대 30초입니다. Gateway/DB 변경 신호가 있으면 즉시 무효화하고, 갱신 실패 시 새 내용을 전송하지 않습니다.

웹은 전사를 영속 브라우저 저장소에 보관하지 않습니다. 로그아웃·권한 회수 시 표시와 참조 상태를 비웁니다. 이미 읽거나 다운로드한 사본을 회수할 수 있다고 보장하지 않습니다. 전사·닉네임·LLM 결과는 텍스트로 렌더링하고 Discord allowed_mentions를 명시합니다.

## 요약과 배포

Solar는 원문 단위 분류 → 독립 의미 검증 → 명시적 중복/변경 관계 → 사실 원장 → 원문 기반 회의록으로 처리합니다. 중간 요약을 재요약하지 않습니다. 모든 사실의 인용 범위·원문 버전과 출력/중복/번복/제외 관계를 보존합니다. 결정·업무·담당자·기한은 검증 후 다시 생성하지 않습니다.

성공한 단계는 실행 키(회의·전사 버전·입력 해시·모델·프롬프트/알고리즘 버전)로 재사용합니다. DB job generation과 회의 삭제/버전 경계를 매번 확인하고, 검증 실행의 출력 해시만 채택·게시합니다. 실패 시 전사를 유지하면서 자동 요약 게시를 보류합니다. 세부 저장 구조와 동의 철회 경계는 [사실 원장](fact-ledger.md)에 설명합니다.

JunnnnyServer는 Ubuntu 24.04, 12 CPU·32GB RAM의 기존 서버입니다. 전용 PostgreSQL 볼륨과 Compose 프로젝트를 사용하고, 별도 Cloudflare Tunnel이 api 서비스로 HTTPS 요청을 전달합니다. Node 이미지와 PostgreSQL 이미지는 확인된 digest로 고정합니다. 실제 DAVE 및 팀 인수 시험을 통과하기 전의 배포는 실연동 검증용입니다.

# 근거 기반 사실 원장

공개 HTTP·SSE·회의록 DTO는 그대로 유지한다. 내부 경로는 `Solar.summarize → runFactLedger` 하나이며 이전의 요약 재요약 경로로 우회하지 않는다. 모델은 `solar-pro3-260323`, temperature 0, 단계 병렬 수 기본 3이다. 자동 검증은 사람의 정확성 보증을 대신하지 않는다.

## 추출·검증·작성

1. 고정된 확정 전사 버전을 시간순으로 정렬한다. 원문의 문자 범위로 발언 단위를 만들고, 업무에 붙은 기한·변경 문맥은 함께 둔다. 모든 단위는 서버 ID를 받는다.
2. 최대 20개 원문 단위씩 Solar가 핵심/보충/비내용과 사실 유형을 분류하고, 별도 호출에서 원문을 다시 분류한다. 키가 하나라도 빠진 출력은 형식 오류다. 인사·대기·인용된 공격은 명시적인 제외 사유를 남긴다. 불명확한 내용은 확정하지 않는다. 불명확한 전사 조각을 미결 질문으로 바꾸지 않고 주제의 확인 필요 발언으로 표시한다.
3. 결정·업무 후보는 원문의 명시적 표현을 먼저 검사한다. 별도 Solar 호출이 **그 발언 당시의 의미만** 독립적으로 검증한다. 제안·조건부 의사·회의 진행 발언을 새 업무로 올리지 않는다. 실제 수행 약속/명시적 수신자, 기한 표현도 검증한다. 동명이인·미확인 신원·모호한 날짜는 null이다.
4. 사실 통합은 기존 ID 사이의 중복·명시적 취소/담당/기한 변경만 다룬다. 서버가 명시적 취소/변경 표현이 있는 허용 쌍을 먼저 만들고, 선택된 관계는 별도 Solar 의미 검사로 대조한다. 단순한 향후 변경 제안은 번복이 아니다. 시간 역전, 존재하지 않는 ID, 변경을 말하지 않는 근거는 거절한다. 모든 사실에 출력 경로·중복 대상·번복 대상·제외 사유가 있어야 한다. 두 판정에서 모두 보충 설명으로 분류한 사실은 EXCLUDED와 사유를 남긴다. 결정·업무·제안과 명시적 미정/변경은 보존한다. 엔진·AD·담당·기한 등 중요 용어를 포함한 불명확한 원문은 확인 필요 표시로 보존한다.
5. 회의록은 검증된 사실 원문을 직접 배치한다. 결정·업무·담당자·기한을 모델이 다시 써서 바꿀 수 없다. 제목과 짧은 개요도 고정 문구와 검증된 결정으로 구성한다. 전사 버전/ID/revision/문자 범위/인용문 일치를 확인한다.
6. DB에서 정본 전사와 참가자를 다시 읽어 회의록을 재구성하고 출력 해시를 비교한다. 채택과 Discord 게시 직전에 삭제 상태·작업 generation·입력 버전·검증 실행을 확인한다. 요약 송신은 회의 잠금 안에서 receipt까지 기록하여 삭제 작업이 늦은 게시물을 놓치지 않게 한다. 실패하면 전사는 제공하고 요약을 보류한다.

## 내부 저장소

`004_fact_ledger.sql`은 `summary_runs`, `summary_stages`, `summary_stage_attempts`, `summary_facts`를 추가한다. 원장에는 사실/검증 결과만 저장하며 모델의 내부 reasoning은 저장하지 않는다.

실행 키에는 회의 ID, 전사 버전, 정렬된 입력 해시, 모델, 프롬프트·알고리즘 해시가 들어간다. 입력 해시는 원문·참가자·회의 날짜·사전·마커·누락·부분 기록 정책을 포함한다. 알고리즘/프롬프트 변경 시 같은 입력도 별개 실행이다.

성공한 단계는 재사용한다. 같은 단계의 네트워크·429/5xx·형식 오류는 **최대 2회 재시도, 총 3회 시도**한다. 횟수는 DB에 남으므로 재시작으로 초기화되지 않는다. 의미 검증 실패는 같은 입력을 다시 요청해 통과시키지 않는다. DB journal은 회의 잠금과 job generation으로 오래된 작업자의 기록을 거절한다.

`verification_run_id`와 출력 해시가 검증된 실행과 일치해야 실제 요약을 채택한다. 전사가 바뀌면 새 버전을 예약한다. 삭제는 접근 차단을 먼저 적용하며, 실제 회의 삭제 시 중간 단계와 원장은 FK cascade로 삭제된다. 보관 기간은 전사와 같은 종료 후 180일이다.

## 음성 대기와 철회

StreamPool 슬롯은 CONNECTING/OPEN/CLOSING 동안 유지한다. 실제 socket 종료 전에 슬롯을 반환하지 않는다. 최대 10개, FIFO이며 취소된 대기자는 제거한다. 5초 버퍼가 찬 상태에서 연결될 때 수신 타임라인을 남은 첫 프레임에 맞추고 tick 여유를 둔다. 잘린 앞 구간은 암호화 원음과 복구 범위로 남긴다.

철회는 캡처 gate를 닫고 진행 중 저장/전사 쓰기가 끝난 뒤 응답한다. 자동 파일 복구는 동의 시각을 작업 payload에 보관한다. 철회와 업로드는 같은 동의 잠금으로 직렬화한다. 철회 시 모든 정책 버전의 동의를 철회하고 PENDING/RUNNING 복구 작업의 generation을 올려 취소하며, 재동의해도 이전 응답이 살아나지 않는다. 명시적으로 요청한 과거 음성 재전사는 별도 정책을 유지한다.

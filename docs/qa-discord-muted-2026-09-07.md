# Discord 무음 QA · 2026-09-07

사용자 요청에 따라 마이크를 음소거한 상태로 실제 Discord·웹·DB 경로를 확인했다. 실제 발언 수신이나 10인 스트리밍 시험과 구분한다. 시험 당시 Discord는 마이크 입력 없음(3002) 안내와 새 오디오 장치 안내를 표시했다. 새 장치로 전환하지 않았고 음소거를 확인한 뒤 회의를 시작했다.

## 실제 확인한 동작

- `/회의 상태`: 진행 중인 회의가 없다는 본인 전용 응답.
- 음성방 밖 시작과 동의 전 시작: 각각 시작 조건에 맞게 거절.
- 동의 정책 안내와 본인 동의 저장, `tesitng`에서 1인 무음 회의 시작.
- 실제 음성 연결의 DAVE protocol 1 협상 및 웹 SSE 연결.
- 중복 시작: 같은 회의 ID를 반환하고 추가 회의를 생성하지 않음.
- 1인 회의의 5분 경과 안내와 60초 후 자동 종료.
- 중요 지점 저장, 일시정지와 웹 PAUSED 표시, 공개 고지 후 재개.
- 기록 중 철회: Discord 카드의 기록 대상이 1명에서 0명으로 변경.
- 발언이 없는 회의는 실제 STT·Solar 호출 없이 빈 회의록으로 마감.

## 발견한 결함과 수정

1. 종료된 회의의 이전 안내 버튼이 연장 성공으로 응답했다. 종료 결정과 연장을 같은 row lock으로 처리하고, 종료 후 연장·표시를 차단했다. 종료 카드 및 연장 안내의 제어 버튼도 정리한다.
2. 수동 종료 후 음성 연결을 두 번 `destroy()`해 마감 성공 뒤 오류 응답을 냈다. 모든 종료/실패 정리 경로에서 이미 해제된 연결을 다시 해제하지 않도록 수정했다.
3. Discord OAuth 사용자 멤버 조회가 429를 반환하면서 웹이 권한 확인 503 상태에 머물렀다. OAuth `/users/@me`로 토큰과 사용자 ID를 확인하고, 봇의 해당 길드 멤버 조회로 현재 역할을 확인하도록 수정했다. 429의 Retry-After 동안 재요청을 억제하며 권한이 확인되지 않으면 기록을 노출하지 않는다.
4. 일시적인 snapshot 503 이후 자동 복구가 없었다. 복구 가능한 네트워크/서버 오류를 재시도하고 Retry-After를 반영한다. 401·404는 기존대로 접근을 차단한다.
5. Linux Chromium에서 Blob 다운로드 파일명이 `download`로 바뀌었다. ASCII 파일명을 사용하고 링크 및 Blob URL 해제를 지연해 `.md`·`.txt` 확장자를 보존했다.

근거: [Discord 길드 멤버 API](https://docs.discord.com/developers/resources/guild#get-guild-member), [Discord 요청 제한](https://docs.discord.com/developers/topics/rate-limits). 음성 연결 중복 해제 예외는 고정된 `@discordjs/voice 0.19.2`의 실제 배포 소스에서 확인했다.

- 실제 회의 ID·이벤트·원음/STT/사용량 수치는 `.data/qa/discord-muted-20260907/runtime.json`에 저장한다.
- 무음 상태의 0바이트는 실제 발화 도중 동의를 철회했을 때의 차단 성능을 증명하지 않는다.
- 실제 2인/12인 수신, SSRC 화자 매핑, 겹친 발화, STT 지연과 품질 검증은 남아 있다.
- 이전 64분 오프라인 녹음의 요약 의미 오류·후반 논의 누락은 별도 미해결 사항이다. 해당 요약 실험 변경은 운영에 배포하지 않았다.
- 원격 DB를 SSH 터널로 접근한 로컬 대량 반복 테스트 2개는 30초 제한을 초과했다. 타임아웃 기준을 완화하지 않고 서버 내부의 임시 테스트 스키마에서 재실행했다.
